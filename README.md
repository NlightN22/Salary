# Salary

Проект расчета зарплат и KPI сотрудников. Сейчас рабочая расчетная логика
реализована для B2B-направления, но структура уже разделена так, чтобы позже
добавлять другие направления отдельными модулями.

Исходные Excel-отчеты обрабатываются, расчетные данные веб-сервиса хранятся в
SQLite, а итоговые документы формируются в PDF. Временные JSON-файлы не создаются.

## Быстрый запуск первичного проекта

Из корня проекта:

```bash
./venv/bin/python main.py
```

Что происходит:

1. `main.py` читает Excel из папки `reports/` последнего периода.
2. Расчет выполняется в памяти, итоговые PDF записываются в папку периода.

## Структура проекта

```text
Salary/
├── calculate_salary.py          # совместимый запуск расчета и PDF
├── main.py                      # запуск расчета и генерации PDF
├── requirements.txt             # зависимости Python
├── requirements-dev.txt         # pytest, coverage и HTTP-клиент тестов
├── pytest.ini                   # настройки тестового запуска
├── README.md                    # описание первичного проекта
├── SERVICE_README.md            # описание web-сервиса
│
├── directions/
│   └── b2b/
│       ├── config.py            # настройки KPI B2B
│       ├── calculate_salary.py  # расчет и генерация PDF по B2B
│       ├── manager_salary.py    # расчет менеджеров
│       └── chief_salary.py      # расчет руководителя
│
├── parsers/                     # чтение исходных Excel-отчетов
├── services/                    # поиск файлов, периодов, именование, округления
├── tests/                       # изолированные unit и интеграционные тесты
├── generators/                  # генераторы PDF
├── models/                      # общие модели данных
├── fonts/                       # шрифты для PDF
├── data/<название подразделения>/ # исходные Excel и итоговые PDF по периодам
└── salary_web/                  # web-интерфейс, API и база данных
```

Исходные файлы всегда размещаются внутри папки подразделения. Первичный
расчет B2B читает только папку своего подразделения
`data/B2B-направление/`; общие папки вида
`data/<год>/<месяц>` не используются. Новое направление должно получить свою
папку и передавать свое имя в функции поиска и сохранения.

```text
data/
└── B2B-направление/
    └── 2026/
        └── 6/
            ├── reports/
            │   ├── profit.xls
            │   ├── brand_sales.xlsx
            │   ├── debt.xlsx
            │   ├── Коммуникации за прошедший месяц.xlsx
            │   ├── Отчет по циклу сделки. Итого.xlsx
            │   ├── Табель.xlsx
            │   └── Табель 2.xlsx
            └── Иванов_Иван_2026_июнь.pdf
```

## Исходные файлы

Для расчета нужны следующие отчеты:

| Тип данных | Как определяется файл |
| --- | --- |
| Доход / прибыль | имя содержит `profit` |
| KPI / бренды | имя содержит `brand` |
| Просроченная дебиторская задолженность | имя содержит `debt` |
| Коммуникации | имя содержит `коммуникации` |
| Цикл сделки | имя содержит `цикл` |
| Табель | имя содержит `табель`; можно несколько файлов |

Если обязательного файла нет, расчет остановится с ошибкой и укажет, чего не
хватает. Поиск выполняется только в подпапке `reports/` выбранного периода.

## Где лежат результаты

Результаты сохраняются рядом с подпапкой исходных Excel:

```text
data/<название подразделения>/<год>/<месяц>/
```

Пример:

```text
data/
└── B2B-направление/
    └── 2026/
        └── 6/
            ├── reports/
            │   └── исходные Excel-файлы
            ├── Провальный_Иван_2026_июнь.pdf
            └── Погорельцев_Роман_2026_июнь.pdf
```

В веб-версии расчетный снимок и история ручных изменений хранятся в SQLite.
Отдельные JSON-файлы не создаются.

## Основная расчетная логика

### Менеджеры

Расчет менеджеров находится в `directions/b2b/manager_salary.py`.

В расчет входят:

- бонус от дохода;
- KPI ZIC;
- KPI Лукойл;
- бонус за другие KPI / спецпродукты;
- ответственность за просроченную дебиторскую задолженность;
- цикл сделки;
- коммуникации как справочный раздел;
- дополнительные выплаты;
- оклад по табелю;
- итоговая сумма к выплате.

### Руководитель

Расчет руководителя находится в `directions/b2b/chief_salary.py`.

Руководитель B2B задается в `directions/b2b/config.py`:

```python
CHIEF_EMPLOYEE = "Погорельцев Роман Олегович"
```

Для руководителя используются общие показатели направления и отдельные KPI:

- доход и рентабельность направления;
- цикл сделки по всем менеджерам;
- ZIC по руководителю;
- спецпродукты;
- просроченная дебиторская задолженность по направлению;
- Лукойл;
- чистая прибыль по ключевым клиентам;
- дополнительные выплаты;
- оклад по табелю.

## Основные настройки B2B

Файл настроек:

```text
directions/b2b/config.py
```

В нем задаются:

- процент бонуса от дохода менеджеров;
- базовые суммы KPI;
- веса спецпродуктов;
- порог клиентов с ПДЗ `100 000` и более;
- процент ответственности за ПДЗ;
- стоимость часа;
- руководитель направления;
- базовые суммы и коэффициенты KPI руководителя.

Менять формулы лучше через этот файл, если параметр уже вынесен в конфиг.
Если параметр не вынесен — сначала вынести, потом менять. Хардкод, конечно,
быстрый, но потом он начинает жить как таракан: неубиваемо и везде.

## Описание ключевых файлов

### `calculate_salary.py`

Совместимая точка входа для расчета B2B и генерации PDF.

Фактически вызывает:

```python
directions.b2b.calculate_salary.main()
```

### `main.py`

Основной запуск расчета и генерации PDF из Excel-файлов последнего периода.

Фактически вызывает:

```python
directions.b2b.calculate_salary.main()
```

### `directions/b2b/calculate_salary.py`

Собирает контекст периода, рассчитывает менеджеров и руководителя в памяти и
создает PDF-файлы непосредственно в папке периода.

### `directions/b2b/manager_salary.py`

Формирует расчетные данные менеджеров.

### `directions/b2b/chief_salary.py`

Формирует расчетные данные руководителя направления.

### `parsers/excel_reader.py`

Общий загрузчик Excel-файлов. Используется для `.xls` и `.xlsx`.

### `parsers/profit_parser.py`

Разбирает отчет по доходу, продажам и рентабельности.

### `parsers/brand_parser.py`

Разбирает KPI по брендам, ZIC, Лукойлу и спецпродуктам.

### `parsers/debt_parser.py`

Разбирает просроченную дебиторскую задолженность и список крупных должников.

### `parsers/cycle_parser.py`

Разбирает CRM-отчет по циклу сделки.

### `parsers/comm_parser.py`

Разбирает CRM-отчет по коммуникациям.

### `parsers/timesheet_parser.py`

Разбирает табель и считает часы/оклад.

### `services/calculation_context.py`

Собирает все исходные файлы периода и создает общий контекст для расчетов.

### `services/file_finder.py`

Определяет типы исходных файлов по названию.

### `services/period_finder.py`

Находит последний период только в `data/B2B-направление/<год>/<месяц>/`.

### `services/rounding.py`

Содержит правила округления денежных значений.

### `generators/pdf_generator.py`

Создает PDF расчетки менеджеров.

### `generators/chief_pdf_generator.py`

Создает PDF расчетки руководителя.

## Частые ошибки

### Не найден файл отчета

Проверьте папку периода и название файла. Поиск идет по ключевым словам:
`profit`, `brand`, `debt`, `коммуникации`, `цикл`, `табель`.

### Excel не читается

Обычно причина — поврежденный файл или временный файл Excel вида `~$...`.
Откройте файл в Excel и сохраните заново.

### Нет сотрудника в расчете

Проверьте написание ФИО в исходных отчетах. Разные отчеты должны называть
сотрудника одинаково или хотя бы достаточно похоже для текущих парсеров.

### PDF не совпадает с ожиданием

Проверяйте в таком порядке:

1. Исходный Excel.
2. Расчетные данные сотрудника в SQLite.
3. PDF.

PDF формируется по расчетным данным, сохраненным в SQLite.

## Web-версия

Web-сервис живет отдельно в `salary_web/` и описан в
[`SERVICE_README.md`](SERVICE_README.md).

Коротко: web-версия добавляет авторизацию, права по направлениям, загрузку
отчетов через браузер/API, SQLite/PostgreSQL, ручные корректировки, генерацию
PDF и API для интеграции с 1С/CRM.

Для web-версии добавлена Docker-обвязка:

```bash
cp .env.example .env
# Заполните SALARY_SESSION_SECRET и SALARY_ADMIN_PASSWORD в .env
docker compose up --build
```

Подробности — в разделе Docker файла [`SERVICE_README.md`](SERVICE_README.md).
