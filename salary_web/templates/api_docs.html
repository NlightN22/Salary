API

API позволяет внешней системе загрузить отчёты за месяц, проверить комплект, создать расчёты и скачать готовые PDF без ручной работы в веб-интерфейсе.

Основной формат адресов для внешних систем: /api/departments/b2b/periods/2026/6/.... Здесь b2b — код направления, 2026 — год расчёта, 6 — номер месяца. Например, /api/departments/b2b/periods/2026/6 означает расчётный период «июнь 2026 года» по направлению B2B.

Перед началом

Все примеры ниже используют текущий адрес сервера: {{ api_base_url }}. Если сервис будет открыт не локально, а на другом домене, примеры автоматически покажут новый адрес.

Внешние системы должны передавать API-ключ в заголовке X-API-Key. Ключ создаётся в админке и привязывается к разрешённым направлениям. 

X-API-Key: sk_salary_...

Вход в браузере не заменяет API-ключ. Если ключ отсутствует, неверный или выключен, сервер вернёт HTTP 401:

{
  "detail": "Требуется API-ключ"
}

Если ключ есть, но у него нет доступа к направлению, сервер вернёт:

{
  "detail": "Нет доступа к подразделению"
}

Публичные методы без входа: GET /api/health, GET /api/commands, GET /openapi.json.

Для внешних интеграций используй адреса /api/departments/{department_code}/... и заголовок X-API-Key. API требует указания подразделения и действующего API-ключа.

Первый запуск: куда вставлять команды

  1. Попросите администратора открыть «Админка», создать API-ключ и дать ему доступ к нужному подразделению. Скопируйте ключ целиком. sk_salary_... в примерах — заглушка, а не рабочий ключ.
  2. Уточните в админке код подразделения, например b2b. В API используется код, а не название «B2B-направление» из адреса веб-страницы.
  3. На macOS нажмите Cmd + Пробел, введите «Терминал» и откройте приложение. На Linux откройте терминал. Команды ниже предназначены для этих систем. В Windows откройте PowerShell, замените curl на curl.exe и объедините строки команды в одну, убрав символы \ в концах строк.
  4. Нажмите «Копировать» у нужного примера. Перед выполнением замените ключ, b2b, год и месяц на свои значения. 2026/6 означает июнь 2026 года.
  5. Вставьте команду в терминал и нажмите Enter. Выполняйте команды по одной: сначала проверьте ответ, затем переходите к следующей.

GET получает данные; POST запускает действие и может менять данные. Не выполняйте примеры загрузки и пересчёта на рабочем периоде только ради проверки связи: для этого достаточно /api/health.

Ключ — секрет, как пароль. Не публикуйте его, не отправляйте в переписку и не включайте в снимки экрана. Команды с ключом могут остаться в истории терминала. При утечке отключите ключ в админке и создайте новый.

Если интеграция работает на другом компьютере, 127.0.0.1 указывает на тот компьютер, а не на сервер зарплаты. Используйте выданный администратором сетевой адрес сервера.

Коротко: как получить PDF

Во всех примерах ниже используется направление B2B и период июнь 2026 года: b2b — код направления, 2026 — год, 6 — июнь. Для другого месяца нужно заменить эти две части адреса.

  1. Проверить, что сервер доступен: GET /api/health.
  2. Создать период: POST /api/departments/b2b/periods/2026/6.
  3. Загрузить все отчёты: POST /api/departments/b2b/periods/2026/6/reports/{report_type}.
  4. Проверить комплект отчётов: POST /api/departments/b2b/periods/2026/6/validate.
  5. Создать расчёты и PDF: POST /api/departments/b2b/periods/2026/6/pdf.
  6. В ответе взять api_download_url.
  7. Скачать файл: GET /api/departments/b2b/periods/2026/6/calculations/{calculation_id}/pdf/download.

Важно: загрузка или замена отчёта удаляет автоматические расчёты этого периода, их ручные корректировки, дополнительные выплаты и связанные PDF. Полностью ручные расчётки сохраняются. Сначала загрузите все исходники, затем считайте зарплату.

Что означают основные слова

Термин Значение
department_code Код направления из админки. Например, b2b.
period Расчётный период: год + месяц + направление.
year Год расчёта. Например, 2026.
month Номер месяца от 1 до 12. Например, 6 — июнь.
report_type Тип исходного отчёта. Список типов указан ниже.
calculation Расчёт одного сотрудника за конкретный период.
calculation_id Внутренний ID расчёта в базе. Его нужно брать из списка расчётов периода.
snapshot Сохранённые данные расчёта, на основании которых формируется PDF.
api_download_url API-ссылка для скачивания PDF.

Важно: что такое calculation_id

calculation_id — это внутренний ID конкретного расчёта в базе. Это не номер сотрудника в месяце и не порядковый номер строки в таблице.

Например, адрес /api/departments/b2b/periods/2026/6/calculations/2 означает: «получить расчёт с ID 2, но только если этот расчёт относится к направлению b2b и июню 2026 года».

Если расчёт 2 относится к другому месяцу или другому году, сервер вернёт ошибку 404. Это сделано специально, чтобы случайно не получить расчёт не за тот период.

  1. Сначала получи список расчётов периода: GET /api/departments/b2b/periods/2026/6/calculations.
  2. В ответе найди нужного сотрудника и его id.
  3. Этот id используй в адресах /calculations/{calculation_id} и /pdf/download.

Коротко: не надо угадывать calculations/1, calculations/2 и так далее. Сначала список, потом конкретный расчёт. Иначе это не API, а рулетка с зарплатами.

Методы

Основные методы для внешних систем — это адреса с /api/departments/{department_code}/.... Они требуют заголовок X-API-Key и проверяют доступ ключа к конкретному направлению.

Метод Адрес Что делает
GET /api/health Проверяет связь с сервером. Если сервер работает, вернёт {"status":"ok"}.
GET /api/commands Возвращает список доступных API-команд.
GET /openapi.json Возвращает полную техническую схему API в формате OpenAPI.
POST /api/departments/{department_code}/periods/{year}/{month} Создаёт период по конкретному направлению. Требует X-API-Key.
GET /api/departments/{department_code}/periods/{year}/{month} Возвращает период конкретного направления. Требует доступ ключа к направлению.
POST /api/departments/{department_code}/periods/{year}/{month}/reports/{report_type} Загружает отчёт в конкретное направление и период.
POST /api/departments/{department_code}/periods/{year}/{month}/validate Проверяет комплект отчётов конкретного направления и периода.
POST /api/departments/{department_code}/periods/{year}/{month}/calculate Создаёт JSON-расчёты без PDF.
POST /api/departments/{department_code}/periods/{year}/{month}/pdf Создаёт расчёты и PDF по конкретному направлению.
GET /api/departments/{department_code}/periods/{year}/{month}/calculations Возвращает список расчётов конкретного направления и периода.
GET /api/departments/{department_code}/periods/{year}/{month}/calculations/{calculation_id} Возвращает конкретный расчёт внутри указанного направления и периода.
GET /api/departments/{department_code}/periods/{year}/{month}/calculations/{calculation_id}/pdf/download Скачивает PDF конкретного расчёта.

Статусы и типовые ошибки

Код Когда бывает Что делать
200 Запрос выполнен успешно. Использовать данные из ответа.
303 В веб-формах после сохранения. Для API обычно не нужен. Для API использовать адреса, начинающиеся с /api/.
400 Неверные данные, нечитаемый файл, неполный комплект отчётов или ошибка расчёта. Проверить текст поля detail в ответе.
401 API-ключ отсутствует, неверный или выключен. Передать действующий ключ в X-API-Key. Вход в браузере не поможет.
403 У API-ключа нет доступа к указанному подразделению. Попросить администратора разрешить это подразделение для ключа.
404 Период, расчёт или PDF не найден. Проверить год, месяц и calculation_id.
422 В запросе пропущен обязательный параметр или неверен его формат. Проверить поле detail. При загрузке файл должен передаваться в поле file, год и месяц — числами.

Пример ошибки: 

{
  "detail": "Расчет не найден в указанном периоде"
}

Примеры

В примерах 2026/6 — это июнь 2026 года: 2026 — год, 6 — месяц. Нажми «Копировать», чтобы забрать команду целиком.

1. Проверить связь с сервером

curl -X GET {{ api_base_url }}/api/health

Если сервер доступен, ответ будет: {"status":"ok"}.

2. Получить список доступных API-команд

curl -X GET {{ api_base_url }}/api/commands

Ответ содержит список API-адресов, методов и технических имён обработчиков.

{
  "commands": [
    {
      "path": "/api/departments/{department_code}/periods/{year}/{month}/pdf",
      "methods": ["POST"],
      "name": "generate_department_period_pdfs_api"
    }
  ]
}

3. Получить полную техническую схему API

curl -X GET {{ api_base_url }}/openapi.json

Это стандартная OpenAPI-схема FastAPI. Она удобна для разработчиков и интеграций, которым нужен машинно-читаемый список методов.

4. Создать период

curl -X POST {{ api_base_url }}/api/departments/b2b/periods/2026/6 \
  -H "X-API-Key: sk_salary_..."

Эта команда создаёт период за июнь 2026 года: 2026 — год, 6 — июнь.

Пример ответа:

{
  "id": 1,
  "year": 2026,
  "month": 6,
  "status": "draft",
  "reports": [],
  "calculations": [],
  "validation": {
    "complete": false
  }
}

5. Загрузить отчёт

curl -X POST {{ api_base_url }}/api/departments/b2b/periods/2026/6/reports/profit \
  -H "X-API-Key: sk_salary_..." \
  -F file=@profit.xlsx

Вместо profit нужно подставить код отчёта из таблицы «Типы отчётов». Загрузка или замена отчёта удаляет автоматические расчёты периода вместе с их ручными корректировками, дополнительными выплатами и PDF. Полностью ручные расчётки сохраняются.

В -F "file=@..." после @ указывается путь к файлу на компьютере, где запущена команда. Если написано только profit.xlsx, файл должен лежать в текущей папке терминала. Для пути с пробелами обязательно оставьте кавычки, как в примере ниже.

Пример с полным путём на macOS

curl -X POST {{ api_base_url }}/api/departments/b2b/periods/2026/6/reports/profit \
  -H "X-API-Key: sk_salary_..." \
  -F "file=@/Users/ВАШЕ_ИМЯ/Documents/Отчеты/profit.xlsx"

Замените весь путь после @ на реальный путь к вашему файлу. Повторите загрузку для каждого обязательного типа из таблицы «Типы отчётов». Один запрос загружает один файл.

Пример ответа:

{
  "id": 1,
  "period_id": 1,
  "report_type": "profit",
  "filename": "profit.xlsx",
  "file_hash": "...",
  "period_status": "missing_reports"
}

6. Проверить отчёты

curl -X POST {{ api_base_url }}/api/departments/b2b/periods/2026/6/validate \
  -H "X-API-Key: sk_salary_..."

Проверьте содержимое ответа, а не только код 200. Загрузка файла ещё не означает, что он читается правильно. Перед расчётом должно быть validated: true. Если это не так, посмотрите missing (чего не хватает) и errors (ошибки файлов), исправьте файлы, загрузите их и повторите проверку.

Проверка нужна, чтобы понять, все ли отчёты загружены и читаются ли они. Если отчёта не хватает или файл не читается, это будет видно в ответе. 

{
  "complete": true,
  "validated": true,
  "missing": [],
  "errors": []
}

7. Создать только JSON-расчёты без PDF

curl -X POST {{ api_base_url }}/api/departments/b2b/periods/2026/6/calculate \
  -H "X-API-Key: sk_salary_..."

Пересчёт удаляет ручные корректировки и дополнительные выплаты у заново рассчитанных сотрудников. Их PDF потребуется создать заново. Полностью ручные расчётки и прежние расчёты сотрудников, которых нет в новых исходниках, сохраняются.

Этот метод нужен, если сначала требуется получить расчёты в базе, проверить их, а PDF сформировать позже. 

{
  "period_id": 1,
  "status": "calculation_created",
  "calculations_created": 5
}

8. Создать расчёты и получить ссылки на PDF

curl -X POST {{ api_base_url }}/api/departments/b2b/periods/2026/6/pdf \
  -H "X-API-Key: sk_salary_..."

Этот метод сразу создаёт расчёты и PDF. Если расчёты уже были, они будут пересозданы на основании текущих загруженных отчётов.

Это пересчёт, а не просто скачивание: ручные корректировки и дополнительные выплаты у заново рассчитанных сотрудников удаляются. Полностью ручные расчётки сохраняются. Чтобы сформировать PDF существующего расчёта с сохранением правок, используйте метод № 11, а для скачивания уже готового файла — метод № 12.

Ответ будет в едином формате:

{
  "period_id": 1,
  "year": 2026,
  "month": 6,
  "pdfs_created": 1,
  "pdfs": [
    {
      "calculation_id": 1,
      "employee": "ФИО",
      "pdf_path": "...",
      "api_download_url": "/api/departments/b2b/periods/2026/6/calculations/1/pdf/download",
      "web_download_url": "/calculations/1/pdf/download"
    }
  ]
}

9. Получить список расчётов периода

curl -X GET {{ api_base_url }}/api/departments/b2b/periods/2026/6/calculations \
  -H "X-API-Key: sk_salary_..."

В ответе будет список расчётов за июнь 2026 года. Из него нужно взять id нужного сотрудника. Именно это значение дальше подставляется вместо {calculation_id}. 

{
  "period_id": 1,
  "year": 2026,
  "month": 6,
  "calculations": [
    {
      "id": 1,
      "employee": "ФИО",
      "status": "calculation_created",
      "has_snapshot": true,
      "has_pdf": true
    }
  ]
}

10. Получить данные конкретного расчёта

curl -X GET {{ api_base_url }}/api/departments/b2b/periods/2026/6/calculations/1 \
  -H "X-API-Key: sk_salary_..."

Здесь 1 — это id из списка расчётов периода. Если поставить 2, сервер будет искать расчёт с ID 2 именно за июнь 2026 года.

Пример укороченного ответа:

{
  "id": 1,
  "period_id": 1,
  "year": 2026,
  "month": 6,
  "employee": "ФИО",
  "status": "calculation_created",
  "total_bonus": 119925.05,
  "salary_total": 161216.57,
  "pdf_path": "...",
  "api_download_url": "/api/departments/b2b/periods/2026/6/calculations/1/pdf/download"
}

11. Создать PDF по одному расчёту

curl -X POST {{ api_base_url }}/api/departments/b2b/periods/2026/6/calculations/1/pdf \
  -H "X-API-Key: sk_salary_..."

Ответ будет в том же формате, только без массива pdfs:

{
  "calculation_id": 1,
  "employee": "ФИО",
  "pdf_path": "...",
  "api_download_url": "/api/departments/b2b/periods/2026/6/calculations/1/pdf/download",
  "web_download_url": "/calculations/1/pdf/download"
}

12. Скачать PDF расчёта

curl --fail --show-error -X GET {{ api_base_url }}/api/departments/b2b/periods/2026/6/calculations/1/pdf/download \
  -H "X-API-Key: sk_salary_..." \
  --output calculation.pdf

Файл сохранится туда, откуда выполняется команда, под именем calculation.pdf. Имя файла можно заменить на любое удобное.

Число 1 замените на calculation_id нужного сотрудника из ответа сервера. Если сервер вернул api_download_url, добавьте перед ним адрес сервера {{ api_base_url }}. API-ключ нужен и для скачивания.

На macOS/Linux команда pwd покажет текущую папку, а ls -l calculation.pdf проверит наличие файла. На macOS откройте её командой open .. Можно указать полный путь после --output, например --output "$HOME/Downloads/calculation.pdf"; папка должна существовать. В PowerShell используйте Get-Location и Get-Item calculation.pdf.

--fail не позволяет записать ответ с HTTP-ошибкой вместо PDF. Если скачивание завершилось ошибкой, не считайте оставшийся на диске старый PDF новым: проверьте ключ, ID и наличие сформированного файла. Текст ошибки можно получить, повторив запрос без --fail и без --output.
